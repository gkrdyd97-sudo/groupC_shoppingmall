# 서종찬 — 트러블슈팅 & 회고

담당: 상품 목록 페이지, 상품 상세 페이지

## 1. 상품 이름은 나오는데 가격만 안 나옴

**문제**
Supabase 연결 후 목록 페이지에서 이름·브랜드는 정상인데 가격만 비어서 나왔다. 타입 에러도 안 떴다.

**접근**
나오는 값과 안 나오는 값의 차이를 비교했다. `name`, `brand`처럼 DB 컬럼명과 철자가 같은 것만 나오고 있었다.

**해결**
DB는 `sale_price`, 코드는 `salePrice`였다. 쿼리 마지막을 `as Product[]`로 단언해놔서 타입스크립트가 검사를 건너뛰고 통과시킨 것이었다. `as`를 걷어내고 `.map()`으로 컬럼명을 하나씩 옮기는 변환 코드를 넣어 해결했다.

## 2. 상품 이미지를 한 번에 못 가져옴

**문제**
이미지는 `FILE_INFO` 테이블에 있는데 `PRODUCTS`와 조인이 안 됐다.

**접근**
Supabase의 중첩 select(`select('*, FILE_INFO(*)')`)를 먼저 시도했으나 계속 빈 값이 나왔다.

**해결**
두 테이블 사이에 외래키가 없고 `gid` 값으로만 연결되는 구조라 중첩 select가 불가능했다. 상품을 먼저 조회한 뒤 그 `gid` 목록으로 `FILE_INFO`를 따로 조회하고, 코드에서 `gid` 기준으로 합치는 방식으로 바꿨다.

## 3. 장바구니에 담을 때 사이즈를 넘길 수 없음

**문제**
상세 페이지에서 사이즈를 `['S','M','L']` 같은 문자열 배열로 들고 있었는데, `CART` 테이블은 `option_id`(uuid)를 요구했다.

**접근**
문자열 'M'으로는 어떤 옵션 행인지 특정할 수 없다는 걸 확인했다.

**해결**
타입을 `sizes: string[]`에서 `options: ProductOption[]`(id + 이름)으로 바꾸고, 버튼이 선택된 옵션의 id를 그대로 서버 액션에 넘기도록 수정했다.

## 회고

처음엔 코드가 한 줄도 안 읽혔다. 에러가 나면 어디서부터 봐야 할지 몰라서 전체를 다시 쓰려고 했다. 이번에 제일 크게 배운 건 **나오는 것과 안 나오는 것의 차이를 비교하는 것**이 디버깅의 시작이라는 점이다. 가격 문제도 "전부 안 나옴"이 아니라 "일부만 안 나옴"이라는 걸 알아챈 순간 범위가 좁아졌다.

타입에 대한 생각도 바뀌었다. `as`로 에러를 지우면 당장은 조용해지지만 문제는 런타임으로 미뤄질 뿐이었다. 에러를 없애는 것과 고치는 건 다른 일이었다.

아쉬운 점은 화면부터 만들고 데이터 구조를 나중에 맞춘 것이다. 사이즈를 처음에 문자열 배열로 잡았다가 장바구니를 붙이는 단계에서 옵션 id가 필요해져 타입을 다시 바꿔야 했고, 그 여파로 상세 페이지와 카드 컴포넌트까지 연달아 고쳤다. 테이블 구조를 먼저 보고 거기에 맞춰 타입을 정했다면 한 번에 끝났을 일이다.
