# 김민지 — 트러블슈팅 & 회고

담당: 메인페이지 / Header, Footer, Nav 공통 컴포넌트

## 1. 목데이터 → Supabase 실데이터 전환

**문제**
홈 화면과 카테고리 네비게이션이 `products.mock.ts`, `mockData.ts` 같은 임시 목데이터를 쓰고 있었고, 실제 DB 스키마와 타입이 맞지 않는 상태였다.

**접근**
이미 Supabase 연동이 끝난 상품 목록 페이지(`getProducts()`)를 정답 패턴으로 삼아, 같은 방식으로 홈/카테고리 영역을 하나씩 교체했다.

**해결**
- 홈 화면: 목데이터 → `getProducts()` 쿼리로 교체, 신상품/베스트 캐러셀을 하드코딩 ID 배열 대신 최신순 slice 방식으로 변경
- `HomeProductCard.tsx`: 옛 필드명(`price`, `images`) → 실제 DB 필드명(`salePrice`, `imageUrl`)으로 수정
- `CategoryNav.tsx`: `MOCK_CATEGORIES` → 직접 작성한 `getCategoryTree()` 쿼리로 교체. flat한 DB row를 `parent_id` 기준으로 맵에 담고 각자 부모의 `children`에 끼워넣는 방식으로 중첩 트리를 조립
- 아무도 쓰지 않게 된 `products.mock.ts`, `mockData.ts` 삭제

## 2. Next.js 16 Cache Components "Blocking Route" 반복 이슈

**문제**
프로젝트에 `cacheComponents: true`가 켜져 있어, `connection()` / `params` / `searchParams` / Supabase 쿼리처럼 요청 시점에만 알 수 있는 값을 Suspense 없이 쓰면 "Blocking Route" 에러가 발생했다. 개발 모드에서는 경고였지만 `npm run build`에서는 빌드 자체가 실패했다.

**접근**
데이터를 가져오는 부분을 별도의 작은 async 컴포넌트로 분리하고, `connection()` + `<Suspense>`로 감싸 나머지(정적인 부분)는 미리 렌더링되도록 하는 패턴을 익혀서 반복 적용했다.

**해결**
`(shop)/layout.tsx`, 홈 화면, `/cart`, `/checkout`, `/checkout/fail`, `/checkout/success`, `/orders/[orderId]` 전부에 같은 패턴을 적용. `checkout/success`에서는 `redirect()`를 `return` 없이 호출해 함수 리턴 타입이 `Promise<void>`로 추론되는 문제도 추가로 발견해, 모든 `redirect()` 호출에 `return`을 붙여 해결했다.

## 3. 장바구니 상태 동기화 버그

**문제**
장바구니에 상품을 담아도 새로고침 전까지 화면에 반영되지 않았다.

**원인**
`CartView.tsx`의 `useState(initialItems)` 초기값이 최초 mount 시 한 번만 반영되는데, Next.js 16의 Activity(페이지 상태 보존) 기능 때문에 페이지를 벗어났다 돌아와도 컴포넌트가 재사용되면서 최신 prop이 반영되지 않았다.

**해결**
처음엔 `useEffect`로 동기화를 시도했으나 "setState in effect" 경고가 발생해, React 공식 권장 패턴인 "렌더링 중 조건부 setState"(이전 `initialItems`와 비교 후 다르면 즉시 갱신)로 변경해 해결했다. 추가로 `{...items, check: true}`(배열 전체 스프레드 오타)로 인해 `price`/`id`가 날아가 NaN/key 경고가 뜨던 버그도 `{...item, ...}`으로 수정했다.

## 4. 카테고리 드롭다운 — `Menu.Item` 안에 `<Link>` 중첩 시 네비게이션 미동작

**문제**
`@base-ui/react`의 `DropdownMenuItem` 안에 Next.js `<Link>`를 자식으로 넣으면, 메뉴 라이브러리가 클릭/키보드 이벤트를 가로채면서 실제 네비게이션이 동작하지 않았다.

**해결**
공식 문서에서 안내하는 `Menu.LinkItem`(링크 전용 컴포넌트)을 `DropdownMenuLinkItem`으로 새로 래핑하고, `render` prop에 `<Link>`를 합성(compose)하는 방식으로 교체해 해결했다.

## 회고

- Next.js 16의 Cache Components는 성능 이점이 크지만, 작은 페이지 하나를 고칠 때도 "이 데이터가 정적인가 동적인가"를 매번 구분해서 Suspense/connection()으로 명시해야 하는 복잡도 비용이 실제로 크다는 걸 체감했다.
- 목데이터에서 실데이터로 전환할 때는 단순히 import만 바꾸는 게 아니라, 타입/필드명까지 연쇄적으로 맞춰야 한다는 걸 배웠다.
- 헤드리스 UI 라이브러리(Base UI 등)를 쓸 때는 "그냥 자식으로 넣으면 되겠지"라고 넘기지 말고, 공식 문서의 전용 컴포넌트(LinkItem 등)를 먼저 찾아보는 습관이 필요하다.
