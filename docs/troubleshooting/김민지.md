# 김민지 — 트러블슈팅 & 회고

담당: 메인페이지 / Header, Footer, Nav 공통 컴포넌트

## 1. 목데이터 → Supabase 실데이터 전환

**문제**
홈 화면과 카테고리 네비게이션이 `products.mock.ts`, `mockData.ts` 같은 임시 목데이터를 쓰고 있었고, 실제 DB 스키마와 타입이 맞지 않는 상태였다.

**접근**
이미 Supabase 연동이 끝난 상품 목록 페이지(`getProducts()`)를 정답 패턴으로 삼아, 같은 방식으로 홈/카테고리 영역을 하나씩 교체했다.

**해결**
- 홈 화면: 목데이터 → `getProducts()` 쿼리로 교체, 신상품/베스트 캐러셀을 하드코딩 ID 배열 대신 최신순 slice 방식으로 변경
- `HomeProductCard.tsx`: 옛 필드명(`price`, `images`) → 실제 DB 필드명(`salePrice`, `imageUrl`)으로 수정
- `CategoryNav.tsx`: `MOCK_CATEGORIES` → 직접 작성한 `getCategoryTree()` 쿼리로 교체. flat한 DB row를 `parent_id` 기준으로 맵에 담고 각자 부모의 `children`에 끼워넣는 방식으로 중첩 트리를 조립
- 아무도 쓰지 않게 된 `products.mock.ts`, `mockData.ts` 삭제

## 2. 신상품/베스트 캐러셀 구현

**구현 내용**
홈 화면 상단에 "NEW ARRIVALS"(신상품)와 "BEST RUNNING PICK"(베스트) 상품을 가로로 넘겨볼 수 있는 캐러셀을 구현했다.

- `ProductSwiper.tsx`: `swiper/react` 라이브러리로 `Navigation`, `Pagination`, `Autoplay` 모듈을 적용 (5초 간격 자동재생, 2.5개씩 보이기, loop). 상품 배열을 받아 `SwiperSlide`로 매핑
- `HomeProductCard.tsx`: 캐러셀 한 칸에 들어가는 상품 카드(이미지, 브랜드, 이름, 가격). 클릭하면 `/products/{id}` 상품 상세로 이동
- 홈 화면(`page.tsx`)에서는 "신상품"은 `getProducts()`로 가져온 전체 상품을 최신 등록순으로 앞 4개, "베스트"는 그다음 4개를 slice해서 보여주는 방식으로 구현 (실제 "베스트 판정" 기준 데이터가 DB에 없어서, 기준이 정해지면 쿼리만 바꿔 끼울 수 있도록 별도 함수로 분리해둠)

**문제**
캐러셀을 `<Suspense>`로 감쌌는데도 빌드 시 다음 에러가 발생했다.
```
Error: Route "/": Next.js encountered the unstable value `Date.now()` while prerendering.
```

**접근**
- 코드 어디에도 직접 `Date.now()`를 쓴 적이 없어서, `getProducts()` → `createServerClient()` 내부, 즉 `@supabase/ssr`/`@supabase/supabase-js` 라이브러리가 세션 체크 등에 쓰는 값일 거라고 추론
- Next.js 공식 마이그레이션 가이드에서 "synchronous IO(`Date.now()` 등)는 `<Suspense>`만으로는 못 피하고, 그 안에서 `connection()`을 먼저 호출해야 한다"는 설명을 확인
- 즉 `<Suspense>`가 있어도 Next.js가 "혹시 미리 만들 수 있나" 시도하다가 라이브러리 내부 깊은 곳의 `Date.now()`를 만나서 막힌 것이었음

**해결**
`NewArriavalSwiper`, `BestPickSwiper` 각각의 맨 앞에 `await connection();`을 추가해, "이 부분은 아예 미리 평가하지 마"라고 명시적으로 선언해 해결했다.

```tsx
async function NewArriavalSwiper() {
    await connection();                       // 추가
    const products = await getProducts();
    return <ProductSwiper products={products.slice(0, 4)} />;
}
```

## 3. Next.js 16 Cache Components "Blocking Route" 반복 이슈

**문제**
프로젝트에 `cacheComponents: true`가 켜져 있어, `connection()` / `params` / `searchParams` / Supabase 쿼리처럼 요청 시점에만 알 수 있는 값을 Suspense 없이 쓰면 "Blocking Route" 에러가 발생했다. 개발 모드에서는 경고였지만 `npm run build`에서는 빌드 자체가 실패했다.

**접근**
데이터를 가져오는 부분을 별도의 작은 async 컴포넌트로 분리하고, `connection()` + `<Suspense>`로 감싸 나머지(정적인 부분)는 미리 렌더링되도록 하는 패턴을 익혀서 반복 적용했다. 페이지 전체가 아니라, "Supabase 쿼리 호출"이나 "params/searchParams 읽기"처럼 요청 시점에만 알 수 있는 값을 쓰는 코드만 쏙 뽑아 별도 함수로 만들고, 그 함수 맨 앞에 `connection()`을 호출한 뒤 `<Suspense>`로 감쌌다.

```tsx
// 페이지 본체 - 정적인 부분만 남음 (껍데기)
export default function HomePage() {
    return (
        <div>
            <HeroVideoBanner />                 {/* 정적 — 안 감쌈 */}
            <Suspense fallback={<div>로딩중...</div>}>
                <ProductSwiper />                {/* 동적 — 이것만 감쌈 */}
            </Suspense>
        </div>
    );
}

// 동적인 부분만 따로 뺀 함수
async function ProductSwiper() {
    await connection();                      // "여긴 요청 와야 끝남" 선언
    const products = await getProducts();    // 진짜 감싸고 싶었던 것: Supabase 쿼리
    return <Swiper products={products} />;
}
```

**해결**

| 파일 | 감싼 대상 |
| --- | --- |
| `(shop)/layout.tsx` | `connection()` 호출 자체 |
| 홈 화면 | `getProducts()` 호출하는 신상품/베스트 캐러셀 부분 |
| `/cart` | `getCart()` 호출 부분 |
| `/checkout` | `searchParams` 읽기 + `getCart()` 호출 부분 |
| `/checkout/fail` | `searchParams` 읽기 부분 (DB 호출이 없어 `connection()`은 생략) |
| `/checkout/success` | `searchParams` 읽기 + `getMyOrder()`/`confirmPayment()` 등 결제 승인 로직 전체 |
| `/orders/[orderId]` | `params`/`searchParams` 읽기 + `getMyOrder()`/`getPaymentByOrderId()` 호출 부분 |

`(shop)/layout.tsx`, 홈 화면, `/cart`, `/checkout`, `/checkout/fail`, `/checkout/success`, `/orders/[orderId]` 전부에 같은 패턴을 적용. `checkout/success`에서는 `redirect()`를 `return` 없이 호출해 함수 리턴 타입이 `Promise<void>`로 추론되는 문제도 추가로 발견해, 모든 `redirect()` 호출에 `return`을 붙여 해결했다.

## 4. 장바구니 상태 동기화 버그

**문제**
장바구니에 상품을 담아도 새로고침 전까지 화면에 반영되지 않았다.

**원인**
`CartView.tsx`의 `useState(initialItems)` 초기값이 최초 mount 시 한 번만 반영되는데, Next.js 16의 Activity(페이지 상태 보존) 기능 때문에 페이지를 벗어났다 돌아와도 컴포넌트가 재사용되면서 최신 prop이 반영되지 않았다.

**해결**
처음엔 `useEffect`로 동기화를 시도했으나 "setState in effect" 경고가 발생해, React 공식 권장 패턴인 "렌더링 중 조건부 setState"(이전 `initialItems`와 비교 후 다르면 즉시 갱신)로 변경해 해결했다. 추가로 `{...items, check: true}`(배열 전체 스프레드 오타)로 인해 `price`/`id`가 날아가 NaN/key 경고가 뜨던 버그도 `{...item, ...}`으로 수정했다.

## 5. 카테고리 드롭다운 — 구현부터 DB 연동까지 (제일 까다로웠던 부분)

**요약**: 목데이터 트리 → 실제 DB 연동(`getCategoryTree()` 작성) → Supabase에 하위 카테고리 직접 등록 → 라이브러리 버그로 링크 클릭이 안 됨(`Menu.LinkItem`으로 해결) → "하위 카테고리 목록" 대신 "실제 상품 바로가기"로 기능 재설계. 총 4단계로 진행했다.

### 5-1. 목데이터 트리 → 실제 DB 연동

**문제**
`CategoryNav.tsx`가 `MOCK_CATEGORIES`라는 하드코딩된 트리를 쓰고 있었다. 그런데 이 목데이터는 1~2차 카테고리 밑에, 사실은 **개별 상품**을 3차 카테고리인 것처럼 끼워넣은 가짜 데이터였다 (`{ name: '라이트 러닝 윈드 재킷', productId: 1001 }` 식). 실제 DB(`PRODUCT_CATEGORY` 테이블)는 그런 가짜 깊이 없이 `id`/`name`/`parent_id`/`sort_order`만 있는 평평한(flat) 행들의 모음이었다.

**접근**
1. 이미 완성돼 있던 상품 조회 패턴(`getProducts()`)을 참고해서, 카테고리도 똑같이 "실제 쿼리 함수 하나 만들고 import만 바꾸면 되겠지" 생각했지만, 카테고리 쪽엔 단건 조회(`getCategoryById`)만 있고 **트리 전체를 조립하는 함수가 없어서** 새로 작성해야 했다.
2. DB에서 가져온 평평한 행 리스트를 중첩 트리로 바꾸는 알고리즘을 직접 설계: ① 모든 행을 `id → 객체`(children: [] 포함) 맵으로 만들고, ② 각 객체를 순회하며 자기 `parentId`에 해당하는 객체의 `children`에 자신을 끼워넣고, `parentId`가 없거나(또는 못 찾으면) 최상위(root)로 분류했다.

**해결**
`domains/categories/queries/getCategoryTree.query.ts`를 새로 작성했고, 그 과정에서 겪은 자잘한 버그들:
- import를 `@supabase/ssr`에서 직접 가져와서 생긴 타입 에러 → 프로젝트 공용 래퍼 `@/shared/lib/supabase`로 수정
- `byId.set(...)`을 빼먹어서 맵이 계속 빈 상태로 남아있던 버그
- 실제 테이블에 없는 `deleted_at` 컬럼으로 필터링해서 난 `column does not exist` 에러 → 그 줄 삭제
- `CategoryNav.tsx`에서 `MOCK_CATEGORIES`를 지우는 과정에서, 지웠어야 할 옛날 줄(`const NAV_CATEGORIES = MOCK_CATEGORIES.filter(...)`)을 안 지우고 남겨둬서 "정의 안 된 변수" 에러가 난 적도 있었다.

### 5-2. Supabase에 실제 하위 카테고리 데이터 추가

실제 DB엔 `accessories/tops/shoes/bottoms` 4개 최상위 카테고리만 있고 하위 분류가 없어서, 드롭다운에 아무 것도 안 뜨는(정상이지만 비어보이는) 상태였다. Supabase Table Editor에서 `PRODUCT_CATEGORY`에 새 행을 추가해, `parent_id`에 부모 카테고리(예: SHOES)의 실제 uuid를 넣는 방식으로 하위 카테고리를 만들었다. (이름이 아니라 **uuid 자체**를 넣어야 한다는 점, `active` 컬럼을 `true`로 안 해주면 관리자 화면에서 "숨김" 처리될 수 있다는 점이 헷갈렸던 부분)

### 5-3. 라이브러리 버그 — `Menu.Item` 안에 `<Link>` 중첩 시 네비게이션 미동작

**문제**
하위 카테고리가 드롭다운에 뜨긴 했는데, 클릭해도 페이지 이동이 안 됐다. `@base-ui/react`의 `DropdownMenuItem` 안에 Next.js `<Link>`를 자식으로 그냥 넣어뒀던 게 원인으로, 메뉴 라이브러리가 클릭/키보드 이벤트를 "항목 선택" 용도로 가로채면서 안쪽 `<a>` 태그의 실제 네비게이션이 씹혔다.

**해결**
공식 문서에서 안내하는 `Menu.LinkItem`(링크 전용 컴포넌트)을 `DropdownMenuLinkItem`으로 새로 래핑하고, `render` prop에 `<Link>`를 합성(compose)하는 방식으로 교체했다.
```tsx
<DropdownMenuLinkItem
    render={<Link href={`/products/${product.id}`} className="..." />}
>
    {product.name}
</DropdownMenuLinkItem>
```

### 5-4. 기능 변경 — "하위 카테고리 목록" → "실제 상품 바로가기"

고치고 보니 원래 원했던 건 "하위 카테고리 이름을 누르면 그 카테고리 상품 목록으로 가는 것"이 아니라, **드롭다운에서 바로 특정 상품의 상세 페이지로 들어가는 것**이었다 (옛날 목데이터가 가짜로 흉내내던 그 동작을 실데이터로 재현하고 싶었던 것). 그래서 하위 카테고리 이름 대신, 그 카테고리에 실제로 등록된 상품들을 보여주도록 구조를 바꿨다.

- 이미 있던 `getProducts(category)` 쿼리를 재사용해, 카테고리별로 상품 최대 5개를 가져와 드롭다운에 상품명으로 노출
- 각 항목의 `href`를 `/products?category=...`(목록)가 아니라 `/products/${product.id}`(상세)로 연결
- `CategoryDropdown`이라는 async 컴포넌트를 새로 분리해서, 카테고리 하나당 `getProducts(cat.name)`을 호출하도록 구성

마지막엔 `className` 오타(따옴표 꼬임, `text-gray=700`처럼 하이픈이 등호로 잘못 들어간 것)도 있었고, 코드를 다 고쳤는데도 화면에 반영이 안 돼서 당황했는데 **dev 서버를 껐다 켜니 해결**됐다 — Server Component 수정은 Fast Refresh로 완전히 반영 안 될 때가 있다는 걸 다시 한번 확인했다.

## 회고

- Next.js 16의 Cache Components는 성능 이점이 크지만, 작은 페이지 하나를 고칠 때도 "이 데이터가 정적인가 동적인가"를 매번 구분해서 Suspense/connection()으로 명시해야 하는 복잡도 비용이 실제로 크다는 걸 체감했다.
- 목데이터에서 실데이터로 전환할 때는 단순히 import만 바꾸는 게 아니라, 타입/필드명까지 연쇄적으로 맞춰야 한다는 걸 배웠다.
- 헤드리스 UI 라이브러리(Base UI 등)를 쓸 때는 "그냥 자식으로 넣으면 되겠지"라고 넘기지 말고, 공식 문서의 전용 컴포넌트(LinkItem 등)를 먼저 찾아보는 습관이 필요하다.
