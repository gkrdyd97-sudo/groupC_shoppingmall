# 정학용 — 트러블슈팅 & 회고

담당: Git 관리, 인증·회원 관리, 관리자 페이지 (로그인/회원가입, 마이페이지, 게시판, 관리자 대시보드)

## 1. 게시판 — 화면 설계(mock)와 실제 DB 구조가 다름

**문제**
화면에 있던 조회수·답변상태 컬럼이 `POSTS` 테이블에 없음. DB 스키마 문서도 없었음.

**해결**
Supabase에 직접 요청해서 실제 컬럼을 확인함. 없는 기능은 제외하고, `category` 컬럼으로 Q&A 문의 유형을 구현함. snake_case → camelCase 변환은 `toPost()` 한 곳에서 처리함.

**상태**: :white_check_mark: 해결 / :small_red_triangle: Q&A 답변 기능은 컬럼 추가 협의 필요

## 2. 회원 — 회원정보 조회·수정이 동작하지 않음

**문제**
기존 회원정보 수정 코드가 조회도 수정도 실패함.

**원인**
테이블 이름을 `profiles`(소문자)로 썼는데, 실제 테이블은 `PROFILES`(대문자)임.

**해결**
팀 코드와 실제 DB를 대조해서 원인을 찾음. Server Action(`profile.action.ts`)으로 새로 작성하고 기존 파일은 삭제함.

**상태**: :white_check_mark: 해결

## 3. 기존 로그인·회원가입 구조가 가이드 패턴과 다름

**문제**
브라우저에서 Supabase를 직접 호출하고, 입력칸마다 `useState`를 씀. 칸별 에러 표시도 불가능했음.

**원인**
프로젝트 가이드의 `useActionState` + Server Action + `ActionState` 패턴이 적용되지 않은 상태였음.

**해결**
Server Action(`login/register/profile.action.ts`)으로 전환하고, 검사 로직은 `authValidation.ts`로 분리함.

**상태**: :white_check_mark: 해결 (단위 테스트 20개)

## 4. 중복 이메일로 가입했는데 성공처럼 보임

**원인**
Supabase는 이메일 인증이 켜져 있으면 가입 여부를 숨기려고 에러 대신 빈 `identities`를 돌려줌.

**해결**
에러 코드 `user_already_exists`와 `identities.length === 0` 두 경우를 모두 중복으로 처리함.

**상태**: :white_check_mark: 해결

## 5. 관리자도 로그인하면 메인으로 이동

**원인**
회원 유형(`user_type`)은 Auth가 아니라 `PROFILES`에 저장되어 있음.

**해결**
로그인에 성공하면 `user_type`을 조회해서, `ADMIN`이면 `/admin`으로 보냄(`getLoginRedirectPath`).

**상태**: :white_check_mark: 해결
